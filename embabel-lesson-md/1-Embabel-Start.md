# 简介

Embabel 是Spring框架开创者**Rod Johnson**最新开源的Kotlin项目。 其是一个基于JVM的Agent框架, 与其他Python的Agent框架最主要的特征在于

1. 规划步骤 -
   该框架从用户的代码中发现操作和目标，并可以根据用户或其他系统输入，规划出最合适的目标。这实现了卓越的可扩展性。例如，您无需重新连接状态机即可添加功能。规划是通过非LLM人工智能算法完成的，该算法提供了一种智能、确定性和可解释性的规划方法。
2. 领域模型 - 该框架鼓励用户使用Kotlin Data Class或者Java Records, 确保类型安全, 可工具化且易于重构。

# Agent框架的意义

难道 LLM 还不够聪明，无法直接解决我们的问题吗？MCP 工具难道不正是我们所需要的，能够帮助它们解决复杂问题吗？

不。MCP 是向前迈出的重要一步，Embabel 当然也欣然接受它，因为它让处理多个模型变得更容易。但是，有很多理由需要更高级别的编排技术，尤其是对于业务应用程序而言。以下是一些最重要的原因：

- *可解释性*：解决问题时为什么要做出这样的选择？
- *可发现性*：MCP 回避了这个重要问题。我们如何在每个节点找到合适的工具，并确保模型在选择工具时不会感到困惑？
- *能够混合模型*，这样我们就不会依赖于上帝模型，而是可以使用本地、更便宜、私有的模型来完成许多任务
- 其他, 例如能够在流程任意一点注入安全防护措施, 大规模Agent的组合, 对数据库等敏感的系统以更安全的控制与集成。

# Why Not Python?

Python 一直是人工智能领域的主导语言。目前，每个开发者都需要精通 Python。然而，人工智能比*Gen AI*更为广泛。Python
为更广泛的人工智能领域提供了一个强大的生态系统，其中包括[TensorFlow](https://www。tensorflow。org/)、[PyTorch](https://pytorch。org/)
和许多其他库。使用 Gen AI，我们不需要做类似的低级工作。我们通过简单的 HTTP 调用来链接多个 LLM。

都远远领先于 Python，并且很可能持续保持领先地位。==**
